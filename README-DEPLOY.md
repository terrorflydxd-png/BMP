# ЦехУчёт онлайн — бесплатный запуск

Эта версия работает не на одном компьютере, а на сервере в интернете. Открыть её можно с любого компьютера и с телефона рабочего, данные у всех общие.

Схема такая:

- **Render** — бесплатно запускает само приложение и даёт ссылку вида `https://...onrender.com`.
- **Neon** — бесплатная база PostgreSQL, где хранятся задачи, станки и история. Данные не пропадают при перезапуске Render.
- **GitHub** — бесплатное хранилище файлов проекта, из которого Render берёт код.

Карту привязывать не нужно. Все три сервиса есть в бесплатных тарифах. Лимиты у них могут меняться, но для одного цеха их достаточно.

> Почему не SQLite? На бесплатном Render файл SQLite стирается при перезапуске. Поэтому база вынесена в Neon и переживает перезапуски и обновления.

---

## Что понадобится

1. Аккаунт GitHub — `github.com`.
2. Аккаунт Neon — `neon.tech`.
3. Аккаунт Render — `render.com` (вход через GitHub).
4. 15–20 минут на первый запуск.

---

## Шаг 1. Загрузите файлы на GitHub

1. Войдите на GitHub и нажмите **New repository**.
2. Название: `ceh-uchet`. Выберите **Private** (закрытый). Нажмите **Create repository**.
3. На странице пустого репозитория нажмите **uploading an existing file**.
4. Перетащите в окно содержимое папки `ceh_cloud` **без папки `data` и без файла `.env`**:
   - `app.py`
   - `requirements.txt`
   - `render.yaml`
   - `Dockerfile`
   - `README.md`
   - `README-DEPLOY.md`
   - папку `static` целиком
5. Нажмите **Commit changes**.

Важно: `render.yaml` должен лежать в корне репозитория, рядом с `app.py`.

---

## Шаг 2. Создайте базу в Neon

1. Зарегистрируйтесь на `neon.tech` через GitHub или e-mail.
2. Нажмите **New Project**. Название — `ceh-uchet`. Регион выберите ближайший, например **Frankfurt** (он же `eu-central-1`).
3. После создания откройте **Connection string** / **Connect**.
4. Скопируйте строку, которая начинается с `postgresql://` и содержит `sslmode=require`. Лучше выбрать вариант **Pooled connection** — он надёжнее для бесплатного тарифа.
5. Сохраните строку в надёжном месте. Это пароль от базы, никому его не передавайте.

---

## Шаг 3. Запустите приложение на Render

1. Войдите на `render.com` через GitHub.
2. Нажмите **New +** → **Blueprint**.
3. Выберите репозиторий `ceh-uchet`. Render сам прочитает `render.yaml`.
4. Render покажет список переменных. Заполните:

   **DATABASE_URL** — вставьте строку из Neon.

   **ACCESS_PASSWORD** — придумайте длинный пароль латиницей и цифрами, например `Ceh-2026-Start`. Это общий пароль для входа на сайт, его будут вводить все. Логин — `ceh`.

   **SEED_PINS** — необязательно. Сюда можно вставить свои PIN-коды в формате JSON, например:

   ```json
   {"u1":"4821","u2":"7390","w1":"3101","w2":"3102"}
   ```

   Ключи: `u1` — директор, `u2` — мастер, `w1`…`w12` — рабочие. Если оставить поле пустым, останутся стандартные PIN из демо (1111, 2222, 3101…). Для реальной работы лучше задать свои.

5. Нажмите **Apply** / **Create**. Render начнёт сборку. Первый запуск занимает 2–5 минут.
6. Когда статус станет **Live**, откройте ссылку вверху страницы Render.

Если Render попросит выбрать регион, выберите **Frankfurt** — он ближе к Беларуси. Если его нет, подойдёт любой европейский.

---

## Шаг 4. Первый вход

1. Откройте ссылку Render. Браузер спросит логин и пароль:
   - логин: `ceh`
   - пароль: тот, что вы указали в `ACCESS_PASSWORD`.
2. После этого появится экран «Вход в цех». Введите PIN директора: `1111` (или свой, если задали `SEED_PINS`).
3. Проверьте разделы «Задачи», «Станки», «История». Нажмите «Поставить задачу» — если форма открывается, сервер работает.

Если браузер не спрашивает пароль, а сразу показывает приложение — значит, `ACCESS_PASSWORD` не сохранился. Вернитесь в Render → **Environment** и добавьте его вручную, затем **Manual Deploy** → **Deploy latest commit**.

---

## Шаг 5. Подключите рабочих

1. Отправьте рабочим ссылку Render и общий пароль доступа (`ACCESS_PASSWORD`).
2. Каждый открывает ссылку в браузере телефона: Chrome на Android или Safari на iPhone.
3. Вводит свой PIN. Например, Игорь Петров — `3101`.
4. Чтобы ссылка была под рукой, добавьте её на главный экран:
   - **iPhone/Safari:** «Поделиться» → «На экран “Домой”».
   - **Android/Chrome:** меню ⋮ → «Добавить на главный экран».

PIN запоминается на 7 дней. Общий пароль браузер тоже запоминает. Если телефон потерялся, смените `ACCESS_PASSWORD` в Render и PIN этого рабочего.

## Как это работает с данными

- Все задачи, станки и история лежат в Neon. Перезапуск Render, обновление кода и сон бесплатного тарифа данные не удаляют.
- Кнопка «Сбросить демо-данные» в «Настройках» удаляет всё и заново создаёт 8 станков и 12 задач. Нажимайте её только до начала реальной работы.
- История перемещений не удаляется: каждая запись хранит автора, время, старый и новый станок, причину и комментарий.
- Выгрузка истории в CSV доступна директору и мастеру.

## Бесплатный тариф: что важно знать

- Render бесплатно даёт 750 часов в месяц. Одного приложения это хватает на круглосуточную работу (в месяце около 744 часов).
- После 15 минут без запросов Render «засыпает». Первый утренний вход может занять до минуты. Это нормально, не ошибка.
- Чтобы не ждать по утрам, можно бесплатно «будить» приложение по расписанию:
  1. Зарегистрируйтесь на `cron-job.org`.
  2. Создайте задачу: URL — `https://ваша-ссылка.onrender.com/api/ping`, интервал — каждые 10 минут, дни — рабочие, время — с 7:00 до 19:00.
  3. Этот адрес не трогает базу, поэтому Neon продолжит спать и не потратит лимит.
- Neon бесплатно даёт 0,5 ГБ хранилища. Для текстовых задач и истории этого хватает надолго. Если лимит кончится, база перейдёт в режим только чтения — тогда нужно перейти на платный план или почистить старые данные.
- Ссылка `onrender.com` бесплатна. Свой домен не обязателен.

## Безопасность

- Обязательно задайте `ACCESS_PASSWORD`. Без него сайт открыт любому, кто узнал ссылку.
- Смените стандартные PIN (1111, 2222, 3101…), если работаете не с демо-данными. Это делается через `SEED_PINS` **до первого запуска**; если база уже создана, сначала нажмите «Сбросить демо-данные», затем перезапустите Render с новыми `SEED_PINS`.
- Не публикуйте ссылку и пароль в открытых чатах. Для цеха достаточно закрытого чата или листа на стене.
- Директор и мастер имеют одинаковые права. Не давайте PIN директора рабочим.
- Пароль базы Neon никому не передавайте. Если он попал в чужие руки, в Neon можно перевыпустить пароль и обновить `DATABASE_URL` в Render.

---

## Если что-то не работает

- **Сайт долго грузится** — Render просыпается, подождите 60 секунд и обновите страницу.
- **Ошибка 401 при открытии** — неверный пароль доступа. Логин `ceh`, пароль — `ACCESS_PASSWORD`.
- **Ошибка 500 / «База недоступна»** — проверьте `DATABASE_URL` в Render → Environment. Строка должна начинаться с `postgresql://`.
- **Не пускает по PIN** — проверьте, что PIN есть в `SEED_PINS` или используется стандартный. После смены PIN нажмите «Сбросить демо-данные».
- **Render пишет build failed** — откройте Logs и пришлите текст ошибки. Чаще всего это опечатка в `DATABASE_URL` или не загрузилась папка `static`.
